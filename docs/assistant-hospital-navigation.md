# 院内助手与流光导航

更新日期：2026-10-04

## 连接与等待处理

本轮线上基线中，普通推荐约 2 秒完成，复杂模型规划约 6–12 秒完成，未稳定复现用户网络下的原始报错。代码检查和故障注入确认了两处可靠性缺口：前端收到 `RUN_FINISHED` 后仍等待 TCP 关闭；异常会覆盖已显示的回答。

- `parking-stream.ts` 以 AG-UI 运行结束事件为边界，结束后释放 reader，不接受迟到的心跳或连接错误。
- 提前断流保留部分回答与工具结果，区分手动停止、110 秒客户端超时、HTTP 网关错误，不自动重复执行场景动作。
- 共享后端的停车模型规划为 60 秒总预算；HTTP 429/5xx、解析失败和等待超时不重复等待一次完整请求。仅 400/422 的 JSON 格式兼容问题可在剩余预算内重试。
- 推荐、常见医院指南、点位路线、天气等走受控查询，不依赖大模型生成一个简单动作。

## 天气与医院知识

访客模式支持以下问题，不产生大模型调用费用：

```text
今天医院天气怎么样
医院怎么预约挂号
骨科怎么挂号
心内科的病房在哪
我要去住院楼，帮我推荐可以充电的停车区
从B区到住院楼怎么走
结束导航
```

天气固定查询常州，通过座舱已有 MCP 获取 Open-Meteo 当前数据，回答带北京时间和来源；两分钟缓存、日期及数值校验，旧日天气不作为今天回答。未获取到有效数据时说明本次查询未完成，不用知识库历史文字补温度。

医院知识新增 8 篇，涵盖 18 个科室及别名、预约报到、门诊时间、虚构医师排班、退号停诊、4 个示范病区、入出院、检查取药、急诊和无障碍服务。公共指南只作为流程参考；医院名为“某某中医院”，地址为“示范市健康路100号（虚构地址）”，医师使用代号，楼层/病房/排班为演示设定。没有真实患者信息、实时床位、真实余号或预约支付接口。

科室名称查询支持别名，例如“骨科”匹配“骨伤科”。提到病房、病区、护士站或探视时导航到住院楼，不因科室名称误定位门诊。返回知识引用标题，可在座舱知识库中查看新增文档。

## 场景标识生命周期

- 三辆巡行车继续复用原轨迹数据、曲线插值和轮胎转动；移除的只是巡航轨迹线网格，驾驶路径未改动。
- 入口路线、推荐卡片“显示道路路径”、自然语言导航、自动导览都显示独立流光路线。
- 路径采用道路图折线，青色底线、沿弧长匀速流动的白色标识和脉冲终点，共 3 个网格；移动端最多 12 个 thin instances，桌面最多 20 个。
- 导航相机为顶部信息和底部控制留出空间，模型、材质、原始纹理和既有车辆展示不变。
- “结束导航”、结束导览、退出账号、纯净模式、组件销毁均清除路线；新请求替换旧路线。取消在途请求并核对 generation，避免迟到返回重新点亮已结束的路线。
- 暂停导览保留当前路线，继续后切换下一段；界面仍是全屏画布和可隐藏浮层。
