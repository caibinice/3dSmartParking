# 车辆运动与三维保真渲染优化

日期：2026-10-04。范围为三维停车前端；座舱后端、业务数据库和博客内容未改动。

## 转弯问题与修复

原道路约每 0.2 秒一个采样点。位置线性插值，但朝向直接使用当前线段方向，约 92% 的 60Hz 采样帧朝向不变，然后在采样点突然跳变。固定尾随相机忠实跟随这个跳角，因此表现为转弯顿一下，而不只是整场景帧率低。

采用保形三次 Hermite 曲线：内点使用 PCHIP 型加权调和切线，位置和速度连续，车头使用位置曲线的解析导数，不额外给车身或相机加滞后滤波。各段仍落在两个采样点的坐标包络内，保留原路，不跨过建筑抄近路。三条原线路、速度倍率与三辆车保留。闭环首末接缝统一；第三条原轨迹约 0.00634 模型单位的微小位置误差也消除。

| 线路 | 原最大单帧朝向变化（60Hz 轨迹采样） | 修复后 |
| --- | ---: | ---: |
| route-0 | 11.03° | 1.38° |
| route-1 | 26.40° | 4.28° |
| route-2 | 15.09° | 3.74° |

这是轨迹数值采样，不是设备帧率承诺。30Hz 下第二条线路的最大变化由 26.40° 降到 8.00°，不再出现长时间保持方向后突然转向的台阶。

运行时复用车身、四轮的 Quaternion 和相机目标向量；尾随不再先重建角度、再立即覆盖角度。暂停时跳过已初始化的车辆更新，恢复只推进实际新帧时间，不补跑暂停期间的时间。尾随仍保持 **0.65 模型单位水平距离、0.25 模型单位高度**，没有逐渐拉远或因滤波改变距离。

## 无损模型优化

当前工具环境未接入 BlenderMCP，因此使用项目已有 glTF Transform / Meshoptimizer 工具链，不经过改变法线、单位、材质或颜色管理的 DCC 重导出。

`scripts/optimize-gpu.mjs` 只处理索引与顶点布局：

1. 不透明三角形重排以改善顶点缓存局部性。
2. 建筑、玻璃、窗户、景观、地基等透明材质保留原三角形顺序，仅重排顶点存储，保留混合效果。
3. 删除无引用 Accessor，不删除任何绘制三角形；没有再做简化、量化、纹理压缩或分辨率缩减。
4. 对每个被使用的顶点属性逐分量核验；三角形集合及绕序一致，纹理原始字节一致。
5. 原/新 GLB 的节点、场景、材质参数、纹理绑定和采样器 JSON 描述完全一致。轮胎拆分、126 辆停放车的实例矩阵及三条巡行线路未改。
6. 输出写到独立暂存目录，校验后替换；`asset-gpu-report.json` 记录原/新 SHA-256。运行时 `rev=gpu-cache-1` 区分长期缓存。

| 资源 | 优化前字节 | 优化后字节 | 32 项 LRU 缓存模拟的未命中减少 |
| --- | ---: | ---: | ---: |
| 桌面园区 | 18,953,916 | 15,626,580 | 12.47% |
| 手机园区 | 16,444,988 | 13,117,660 | 10.71% |
| 桌面车辆 | 1,420,956 | 1,420,956 | 11.33% |
| 手机车辆 | 1,350,928 | 1,350,928 | 11.73% |

合计减少 **6,654,664 字节**。缓存模拟用于比较索引布局，不等同于实际显存、GPU 耗时或 FPS 增幅。

静态园区与停放车辆模板缓存世界矩阵和已计算的包围信息；动态车辆及轮胎保持更新，仍参与正常视锥和拾取计算。没有冻结整场景活动网格，也没有降低光效、抗锯齿或像素预算来换指标。

## 验证

- 25 项前端测试与资产审计通过：方向、连续朝向、道路包络、闭环接缝、轮胎、暂停恢复、固定尾随、对象复用及原智能体回归；类型检查与生产构建通过。
- 桌面 1440×900、手机 844×390，分别对照全景、建筑近景、停车区、车辆近景，共八组同视角截图。改变的颜色通道比例均小于 0.05%，平均通道差不超过 0.0012（0–255 范围）；模型几何、材质和纹理验证相等。
- 浏览器在第二条线路急转弯附近连续观察 160 个实际渲染帧：最大朝向变化约 4.00°，后退步骤为零；水平距离范围 0.6499999999999996—0.6500000000000006，高度保持 0.25，车轮/车身 Quaternion 始终复用。
- 停放车第 0、63、125 个实例的实际射线拾取全部返回正确序号；静态模板缓存、动态车辆不冻结。
- 全景样本仍为 121 个渲染网格、433,911 个总顶点、约 242 次绘制。桌面画布为 2880×1800，手机横屏画布为 1688×780。本轮不声称整体帧率显著提升；需要进一步区分 CPU、透明层和 Glow 的 GPU 成本。
- 已有精细纹理、招牌、三辆自动巡行车、开场视频、浮层、助手和手机横向布局保留。

线上 release：`20261004032637`，桌面 `/smartParking/` 与手机 `/smartParking/mobile` 均以正常 TLS 校验访问成功。四个线上 GLB 的 SHA-256 与本地清单完全一致；浏览器确认加载 `rev=gpu-cache-1` 新资源。桌面切换巡行车、车辆尾随、返回全景，以及手机 844×390 横屏与 390×844 竖屏横向场景复测通过，控制台无错误。博客与三个子项目健康接口保持 200，五个既有服务保持 active，Nginx 配置检查通过；未重启业务后端。

## 后续优化方向

| 方向 | 收益与实施边界 | 本轮状态 |
| --- | --- | --- |
| 连续轨迹与运动对象复用 | 消除离散朝向；减少动画帧的临时对象 | 已实施 |
| 无损缓存重排与资源清理 | 减少下载与顶点读取；保留全部现有绘制内容 | 已实施 |
| 静态矩阵/包围信息缓存 | 避免不可变网格重复同步；动态车保持实时计算 | 已实施 |
| 透明层与 Glow 分通道计时 | 先测量真实 GPU 成本，再针对重复绘制优化；黑色遮挡物也影响 Glow，不能直接删掉非发光网格 | 下一阶段优先 |
| KTX2/Basis 纹理变体 | 减少纹理上传与显存；法线、Alpha、文字需逐材质对照，保留原 WebP/PNG 回退 | 待专项 A/B |
| 车群空间分块 | 更大园区按空间格子拆分 thin instances，改善视锥裁剪；当前仅 126 辆，先测收益再增复杂度 | 规模扩大时评估 |
| 分材质 LOD 与屏幕误差阈值 | 门窗、招牌、轮毂保留；仅对远处非轮廓几何切换 LOD，避免整体粗减面 | 待专项 A/B |
| BlenderMCP 保真资产工作流 | 导入副本，固定坐标/单位/法线/颜色管理，检查重复隐藏几何与材质槽；保留顶点颜色和玻璃顺序，校验导出后再替换 | 待接入工具 |
| WebGPU 与 shader warm-up | 现有 WebGPU 仍是显式选择；按实际设备对比初始化、纹理、透明与材质编译，不强制切换所有访客 | 保持可选、继续测量 |

优先顺序是 GPU 分通道计时 → 透明/Glow 定向优化 → 纹理压缩变体；激进减面、全局冻结活动网格和低分辨率回退不作为默认优化。
